## Offer snapshot
- Buyer/payer: Platforms/hosts embedding the ingredient (illustrative: a course creator embedding the action layer).
- Offer: B2B2C ingredient: a finished component (e.g. the action layer) embedded in a host's product; the host pays a licence; end users get the job done inside the host.
- Delivery: Embedded component; operator maintains the ingredient; hosts integrate and distribute.
- Price hypothesis (working assumption, not verified willingness-to-pay): Illustrative licence (unvalidated).
- Repeat mechanism: Hosts renew the licence while their product ships the ingredient; end-user usage inside hosts creates the renewal reason.
- Founder's role: Sets integration standards; 0-2 hrs/week.
- Primary satisfaction shape: Tool in the hand (supporting: via the example lane (a course creator embedding the action layer as the example))

## Material assumptions (labelled)
- A-emb: hosts integrate the ingredient competently.
- A-val: the ingredient is a finished component, not a framework.
- A-price: unvalidated.

## Overall interpretation
The ingredient-company structure: the economics are per-host integration work, which is what keeps B2, B7 and B10 at 1. The satisfaction is real but host-filtered (B5=1). This is the structure behind #25's action layer -- as a company, the question is whether hosts buy vs build.
